# Domain Docs

Before exploring a topic, read the root `GLOSSARY.md` and any ADRs in `docs/adr/` that touch the area. If they do not exist, proceed without them; create them when domain terms or decisions are resolved.

Use the glossary's terminology in issues, proposals, hypotheses, and tests. If a needed concept is absent, consider whether it represents a genuine gap in the vocabulary.

If a proposal contradicts an ADR, identify the conflict explicitly and explain why the decision might need revisiting.
